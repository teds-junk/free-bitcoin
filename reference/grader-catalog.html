How each can be tested

GraderOracle, without the golden patchRe-grade of a saved run
diff-containsFails as expectedWorks, if the run saved diffs
diff-not-contains, diff-emptyN/A: an untouched file passes honestlyWorks. Re-grade a trial known to be bad; it must fail
program, run-commandFails as expected, with the script's evidenceNot reliable: the workspace is gone, so it fails every trial. Ours reported no CHANGELOG.md to check and Expected exit code 0, got 1
file-containsNot used in the courseEnds in ERROR: Grader error: Directory '…' does not exist
skill-invocation, tool-calls with requiredFails as expectedWorks: it reads the saved trajectory
tool-calls with only disallowed, max-repeatN/A: an empty trajectory does nothing forbiddenWorks. To see it fail, point it for a moment at a command a saved trial did run
token-budget, turn-count, wall-timeNot used in the courseWorks exactly as in a live run. Test every new budget this way
promptNot used in the courseWorks. One judge call per trial

A run saves diffs only when its eval file has a diff grader. See Lesson 7, Lesson 8, Lesson 18, Lesson 20 and Lesson 23.

Patterns for diff graders

Diff graders see the whole patch, including unchanged lines around each change.

PatternMatches
(?m)^\+.*\(#\d+\)An added line containing a number such as (#42)
(?m)^\+### SecurityAn added line that starts with that heading
(?m)^\+.*\(#64\)An added line citing one particular number

Without (?m), ^ means the start of the whole patch, and a pattern beginning ^\+ can never match. In diff-not-contains that grader can never fail; in diff-contains it can never pass. Lesson 8, Lesson 20

Budget graders

evals/changelog.eval.yaml (under each stimulus's graders)
      - type: token-budget1
        config:
          max: 215000
      - type: turn-count
        config:
          max: 10
      - type: wall-time
        config:
          max: 30s2
  1. No name, because grader names must be unique across the file. Vally names it from its type and limit: token-budget max 215000.
  2. A time is written with its unit.

Each fails only above max. Over budget, the score falls in proportion to the overrun (28 tokens over printed Score: 100.0% | FAILED), but the grader fails all the same. Our first budgets, just above the median, failed 5 of 29 good trials; about twice the largest typical value failed none. tool-call-count works the same way, counting tool calls. On a run converted from traces the wall time is 0, so wall-time passes anything. Lesson 18, Lesson 25

Graders of the route

evals/release.eval.yaml (since-last-release)
      - type: tool-calls
        name: reads-the-list
        config:
          required:1
            - name: ^(view|bash)$
              pattern: release/merged\.txt
      - type: tool-calls
        name: never-commits
        config:
          disallowed:2
            - name: ^bash$
              command: git (commit|push)
      - type: max-repeat
        name: no-loop
        config:
          max: 33
  1. Each entry is a set of regular expressions that must all match one call: name on the tool's name, command on a shell command, path on a file tool's path, pattern on all the arguments as text. They are unanchored: view alone also matches preview. Tool names we saw: view, edit, apply_patch, bash, skill. Keep a required step as loose as the requirement: a view-only version failed a trial that read the list with cat.
  2. No call may match. Only a saved trial that did the forbidden thing shows this failing.
  3. Four identical results in a row fail. match sets what counts as the same: observation (the default, same result), name (same tool) or name-args. tools limits it to some tools; max_cycle_period also catches A, B, A, B. Lesson 23
evals/release.eval.yaml (tracker-down)
      - type: loop-outcome
        name: stops-retrying
        config:
          should_loop: false1
          max_acceptable_retries: 22
  1. Which answer passes. false, the usual case, passes when the agent did not loop.
  2. Four identical calls in a row are three retries. In one of our trials an agent ran a failing command seven times in a row, and this failed it. Lesson 24

A hidden test with run-command

evals/release.eval.yaml (the end)
    grading_environment:
      files:
        - src: grading/check-release.mjs
          dest: .vally-grading/check-release.mjs1
    graders:
      - type: run-command
        name: every-change-handled
        config:
          command: node .vally-grading/check-release.mjs2
  1. Staged for graders only, so the agent never sees the test.
  2. Passes on exit code 0. expected_exit_code sets another; stdout_contains and stdout_matches check what it prints; timeout defaults to 30 seconds. On a failure the evidence is only Expected exit code 0, got 1; the script's own message is not recorded. Lesson 22

With vally grade --workspace on a run Vally did not start, the grading environment is staged as usual, so a hidden test works there too. Lesson 25

How a script grader reports

A program grader's script prints one result as a line of JSON and exits with 0 whether the check passes or fails. The verdict and the evidence come from what it printed. An exit code other than 0 means the script itself broke, and the trial fails.

evals/grading/check-entry.mjs (the end of the script)
function report(passed, evidence) {
  console.log(JSON.stringify({
    name: "check-entry",1
    kind: "code",
    passed,2
    score: passed ? 1 : 0,
    evidence,3
  }));
  process.exit(0);
}
  1. All five fields are needed. With fewer, Vally reports Grader output did not match schema.
  2. true or false: the verdict.
  3. A sentence saying what was found. It appears in the results as the grader's evidence.
The grader in the eval file
      - type: program
        name: two-entries-in-place
        config:
          program: node
          args:
            - .vally-grading/check-entry.mjs
            - Added=60
            - Fixed=60

Under vally oracle, with the golden patch the evidence read every entry found in Unreleased; without it, no entry citing #60 under Added. A script that only needs pass or fail is simpler as run-command, above.
