Eval file cheat sheet

Verified 2026-11-10 · Vally 0.21.0

Every key this course used in an eval file, an experiment file and .vally.yaml, with the lesson that explains it. Each snippet is from a file we ran, except where it says it was only linted.

An eval file

Only name, stimuli, and each stimulus's name and prompt (or turns) are required.

The top of an eval file
name: changelog1

defaults:
  timeout: 3m2
  judge_model: claude-sonnet-5.53

agent_environment:4
  skills:
    - ../skills/changelog-entry
  files:
    - src: fixtures/notes-cli/CHANGELOG.md
      dest: CHANGELOG.md

stimuli:
  1. Used as a folder name in the results. Lesson 2
  2. How long one trial may take. The unit is required.
  3. The model that judges, for a prompt grader. Lesson 12
  4. Skills and files copied into the workspace before the agent starts. A skill is copied as a whole folder. Paths are relative to the eval file. Lesson 6

Two more keys can go under defaults: model, and reasoning_effort, how much the agent's model reasons before it acts. Accepted efforts depend on the model; in our account claude-haiku-4.5 took none, claude-haiku-5.5 took low to max. Lesson 16

One stimulus, with the keys from lessons 2 to 13
  - name: two-changes
    tags: { tier: quick }1
    prompt: |2
      PR 60 is in. Changelog please.
    agent_environment:3
      files:
        - src: fixtures/notes-cli/CHANGELOG.md
          dest: CHANGELOG.md
    grading_environment:4
      files:
        - src: grading/check-entry.mjs
          dest: .vally-grading/check-entry.mjs
    golden_patch:5
      path: golden/two-changes.patch
    rubric:6
      - One criterion, answerable yes or no.
    graders:7
      - type: diff-contains
        name: cites-60
        turn: 08
        config:
          pattern: '(?m)^\+.*\(#60\)'
  1. Labels for choosing stimuli, in a suite or with vally eval --tag tier=quick. Lesson 21, Lesson 24
  2. The request. Use turns: and a list of requests for a conversation. >- in place of | joins the lines into one, as an app sends it. Lesson 11, Lesson 22
  3. Files for this stimulus only. A file here may not have the same dest as a file in the top-level agent environment.
  4. Files added for graders only, after the agent stops. The source must be somewhere no agent environment copies. Lesson 6
  5. A patch recording a correct answer, for vally oracle. The path must be in the eval file's folder or below. Lesson 7
  6. Criteria for a judge, in plain words. Lesson 12
  7. The checks. With no scoring block, a trial passes only if every grader passes. Names must be unique across the whole file, so budget graders repeated under several stimuli are left unnamed. Lesson 5, Lesson 18. Every grader's options are on the grader catalog.
  8. Limits a grader to one request of a conversation, counted from 0. It sits beside type, not inside config. Lesson 11

Setting up before the agent starts

evals/release.eval.yaml (one stimulus's environment)
    agent_environment:
      files:
        - src: ../tools/list-merged.mjs
          dest: tools/list-merged.mjs
      commands:1
        - "mkdir -p release"
        - "node tools/list-merged.mjs > release/merged.txt"
  1. Shell commands run in the workspace, in order, after the files and skills are copied and before the agent starts. What they create is part of the starting state, so it is not in the patch. Each has 60 seconds unless commandTimeout says otherwise. Quote every entry: one containing a colon and a space is read as a mapping. Lesson 22, Lesson 20
Other environment keys (linted by us, not run)
agent_environment:
  commandTimeout: 2m1
  env:2
    LOG_LEVEL: debug
  git:3
    type: worktree
    ref: v2.1.0
    source: ../my-repo
  mcpServers:4
    db:
      type: stdio
      command: db-serve
      args: ["--port", "5432"]
    api:
      type: http
      url: http://localhost:3000/mcp
  1. The time limit for each setup command.
  2. Environment variables for the agent's process: a mapping of names to values, every value a string (quote numbers). Values can appear in saved trials, so no secrets. Lesson 22
  3. Builds the workspace from a repository: worktree checks out a ref of a repository on your machine, clone takes a url. Explained, not run, in Lesson 22.
  4. MCP servers to attach to the agent's session. Not taught in the course: the shape is from the Eval Spec reference, and lint does not check the keys inside it.

Limits that stop the agent

evals/changelog.eval.yaml (one stimulus, start)
  - name: typo-fix
    prompt: |
      I fixed the typo in the help text for `notes add`
      (it said "tittle"). Put that in the changelog.
    constraints:1
      max_agent_duration: 1m2
  1. Per stimulus only; there is no eval-wide version.
  2. Stops the agent and grades what it had done; the record's endReason reads agent_timeout. max_duration stops the trial and fails it; keep max_agent_duration below it. max_turns is documented but its behaviour at the limit is not, so the course uses the turn-count grader instead. Lesson 18

Making a tool fail

evals/release.eval.yaml (tracker-down's simulation block, shifted left)
simulation:
  tool_overrides:
    shell:1
      patterns:
        - match: list-merged2
          output: "error: tracker did not answer (timeout)"
          is_error: true3
  1. The tool to override. shell, bash and powershell all mean the agent's shell tool. Shell tools can succeed or fail; other tools, such as view, can only fail.
  2. A regular expression tested against the whole command, ignoring case; the first match wins. Calls that match nothing, and tools not named, run for real. A default: beside patterns, with its own output and is_error, answers every call the patterns miss.
  3. The command does not run; the agent gets the output as a failure. Without it, the same output comes back as success. Needs the copilot-sdk executor. Lesson 24

vally simulate record prints a block like this from a saved run's shell calls, as a starting point to edit. Lesson 24

Combining graders into a score

evals/wording-scaled.eval.yaml (the end)
scoring:1
  weights:2
    prompt: 0.5
    diff-contains: 0.5
  threshold: 0.753
  1. Top level, beside stimuli; applies to every stimulus. Without it, every grader must pass.
  2. Keyed by grader type, not name; lint expects them to add up to 1. A type left out counts 0. With a threshold and no weights, every grader counts equally.
  3. The trial passes when its weighted score reaches this, whatever any single grader said. Keep checks that must all hold out of a weighted score. Lesson 14

Not to be confused with a judge's own scoring: scale_1_5 and threshold, inside the prompt grader's config. See Judges and small counts.

Running the agent somewhere else

An eval file's defaults, for a hosted provider (linted, not run)
defaults:
  model: my-model-name1
  executor:
    name: copilot-sdk2
    config:
      provider:
        baseUrl: https://api.example.com/v13
        type: openai4
        apiKeyEnv: MY_PROVIDER_KEY5
  1. The name the provider knows the model by. Vally does not check it against your account's list.
  2. The built-in executor, the part of Vally that runs the agent. Only where it sends model requests changes.
  3. The only required field. Ollama on your own computer: http://localhost:11434/v1, and nothing else.
  4. The kind of interface; openai is the default.
  5. The name of an environment variable holding the key, read from the environment of the vally command. The key itself never goes in the file; lint rejects apiKey. No cost is recorded for these trials, and a judge still goes through your Copilot account. Lesson 17

An executor loaded as a plugin is named by itself, as in executor: release-app, or chosen per run with vally eval --executor release-app. Lesson 26

What Vally refuses, and when

MistakeWhat happens
A misspelt key in a stimulusvally lint reports eval-load-error and lists the allowed keys
A file under files that does not existvally lint reports environment-file-not-found
A grading file staged from inside a skill foldervally lint reports grading-file-src-agent-visible
A stimulus file with the same dest as a top-level fileLint passes; the run stops before any agent starts, with environment-resolution-failed
More than one grader and no scoring blockLint warns scoring-defaults-applied. This is the every-grader-must-pass rule, and is usually what you want. Lesson 14
Two graders with the same name, such as a named budget under every stimulusvally lint reports duplicate-grader-name. Lesson 18
A commands: entry with a colon and a space, unquotedLint passes; every trial ends in ERROR within milliseconds: The "command" argument must be of type string. Lesson 20
An env written as a list, or a number left unquotedvally lint reports environment-env-invalid (our lint, 2026-11-10)
apiKey in a provider blockvally lint reports executor-config-invalid and lists the allowed fields. Lesson 17
apiKeyEnv naming a variable that is not setLint passes; every trial ends in ERROR before the agent starts
A stimulus with simulation, run by an executor that does not support itThat stimulus ends in ERROR before any agent starts, at no cost. Lesson 26

An experiment file

evals/before-and-after.experiment.yaml
name: before-and-after
evals:
  - wording.eval.yaml1
vary: [/environment/skills, /defaults/model]2
baseline: haiku-before3
overrides:
  runs: 34
variants:
  haiku-before:
    overrides:
      model: claude-haiku-4.5
    environment:
      skills: [../skills/changelog-entry-before]
  haiku-after:
    overrides:
      model: claude-haiku-4.5
    environment:
      skills: [../skills/changelog-entry]5
  1. The eval file whose stimuli and graders every variant uses.
  2. The only settings variants may differ in. Anything else stops the run with Experiment drift detected.
  3. The variant the others are compared with.
  4. Settings for every variant. Here, three trials each. An executor set here, as in executor: release-app, applies to every variant. Lesson 26
  5. An empty list, skills: [], means no skill. Lesson 10
evals/cost.experiment.yaml (after lesson 17)
name: cost
evals:
  - changelog.eval.yaml
vary:1
  - /defaults/model
  - /defaults/reasoning_effort
  - /defaults/executor
  - /defaults/timeout
  - /defaults/runs
baseline: haiku-low
overrides:
  runs: 3
variants:
  haiku-low:
    overrides:
      model: claude-haiku-5.5
      reasoning_effort: low2
12 lines hidden: haiku-high, terra-low and terra-high
  qwen-local:
    overrides:
      model: qwen3.5:9b
      timeout: 9m
      runs: 13
      executor:
        name: copilot-sdk
        config:
          provider:
            baseUrl: http://localhost:11434/v1
  1. One path per line. A variant that sets its own executor, timeout or trial count needs that path here; vally experiment run has no --runs or --timeout options. Lesson 17
  2. Reasoning effort varied like the model. Lesson 16's file has four variants: two models at low and high. Lesson 16
  3. Per-variant overrides of the trial count, time limit and executor. Run one variant alone with --variant qwen-local.

Suites and plugins in .vally.yaml

.vally.yaml, in the folder you run Vally from
plugins:
  executor:
    - ./app/vally-executor.mjs
suites:
  quick:
    description: Code graders and budgets, one trial.
    evals:
      - evals/changelog.eval.yaml
    filter: { tier: quick }
  full:
    description: Everything, with loading and the judge.
    evals:
      - evals/changelog.eval.yaml
      - evals/conversation.eval.yaml
      - evals/loading.eval.yaml
      - evals/wording.eval.yaml

A suite is a list of eval files, optionally narrowed to stimuli with a tag. It adds no graders of its own; the quick suite carries budgets because its stimuli do. Lesson 21

plugins.executor loads executor files. Loading one does not select it. Lesson 26
