# Teaching Notes

## Learner preferences
- **Start from scratch.** Ted has used Vally before, mostly through an agent. Treat that as exposure, not mastery (LR-0001).
- **Shareable.** The course creates its own example and names nothing private: no personal repositories, local skills, home-directory paths or account-specific values presented as universal.
- **One story.** A simple skill, different results on different models, evals as the way to make it consistent. Every feature is taught as a way to improve that skill, and every section says whether it is about how to think, how it works, or how to use it.
- **Concepts before commands.** Each idea gets a plain definition and a small example before any command relies on it. Split a lesson rather than rush one. He stopped at the old lesson 4 because `vally oracle` and "golden patch" were used without being explained.
- **Show files, do not query them.** Annotated excerpts first. `jq`, `grep` and `sed` only as an optional aside.
- **No one-line gap markers.** Ted found lesson 2's six "1 field hidden" markers more distracting than the fields (2026-11-10). A marker hides three lines or more, or a line too wide or private, and says what it hides. The rule is now in the teach-me and video-lesson skills and in `check-lessons.js`.
- **Plain shell.** No variables, command substitution or long pipelines.
- **No coined terms.** Plain descriptions (agreed 2026-11-09). Ask before introducing any name.
- **Write as "we".** "In our run", "ours", never "the author" (2026-11-10: "That's how humans write"). The rule and a `voice` check are now in the teach-me skill.
- **Plain titles.** No italicised word in headings.
- **Only the latest Vally.** Nothing about earlier versions.
- **Explain before shelling out.** Every command in a lesson is preceded by a goal line; the same rule applies to me while working.
- **Length follows the content.** "Make it longer if that fits better" (2026-11-09).
- Current industry practice built in, from dated sources, with weak evidence labelled as weak.

## Facts established by running Vally 0.21.0
From the pilot (2026-11-09):
- `vally eval --model a,b,c` runs every stimulus on each model and prints a model summary table.
- Each trial gets a folder `<output-dir>/<timestamp>/<eval name>/<stimulus>/<model>/<trial index>/` holding `workspace.patch` (a git-style diff of what the agent changed), `events.jsonl` and `metadata.json`. The run folder also holds `eval-results.md`, `results.jsonl` and `otel-spans.jsonl`.
- **`--workspace` cannot be combined with several models**: the kept-workspace path has no model in it, so the run stops with `workspace-collision`.
- **Sessions still drop at two workers sometimes** ("Session disconnected while waiting for a response"), and one trial hit the 3-minute timeout. Both are `ERROR`, not a verdict.
- `results.jsonl` trial records carry `model`, `trialIndex`, `status`, `durationMs`, `gradeResult`, `trajectory`, and a cost at `trajectory.metrics.tokenUsage.cost` (unit `nano-aiu`).
- Saved results embed absolute paths from the machine that ran them. Anything shipped in `./verified/` must not include raw results with those paths.
- With the first-draft skill, all three models loaded the skill in every trial and passed a loose `file-contains` grader in every completed trial.
- What the patches showed: `gpt-5.6-terra` invented a pull request number when none was given; all three added an entry for an internal refactor; all three filed a security fix under Fixed; two wrote `## Unreleased` where the file's style is `## [Unreleased]`; two described a fix in implementation words; one dropped a blank line before a new heading.
- `vally init` creates only `evals/hello/eval.yaml`; it does not create `.vally.yaml`.

From authoring lessons 1 to 4 (2026-11-10, `claude-haiku-4.5` and `gpt-5.6-terra`):
- A minimal eval file needs only `name`, `stimuli`, and each stimulus's `name` and `prompt`. `type`, `description` and `graders` are optional; a stimulus with no graders lints and runs.
- `--model <unknown name>` prints the account's model list, exits 1, starts no agent. Used in lesson 1 to list models.
- Folders and `trialIndex` number trials from 0; console lines number them from 1.
- With `--runs`, the report adds Pass Rate, pass@k and pass^k columns and a footnote such as "Flaky (20% minority outcome)". The model summary gives a model a tick only when no trial failed.
- With `--skip-grade` the summary still prints ticks; they mean the trial finished.
- **A stimulus-level file cannot share a destination with a root-level file** (`environment-resolution-failed`, "Conflicting files for destination"). Lint does not catch it; the run stops before any agent starts. So each stimulus names its own changelog.
- The report (`eval-results.md`) has no agent replies. A trial's final reply is `trajectory.output` in `results.jsonl`.
- The per-trial `events.jsonl` is the agent's raw session log (`skill.invoked`, `tool.execution_start`, `assistant.message`). The tidied events (`skill_activation`, `tool_call`) are inside `results.jsonl` at `trajectory.events`. Lesson 9's plan line must say which file it shows.
- Each trial's log ends with its usage: a `claude-haiku-4.5` trial counted 0.33 premium requests and a `gpt-5.6-terra` trial 1.
- `trajectory.metadata.skillsLoaded` lists other skills present in the session besides the one staged (seen: `customize-cloud-agent` and two more). Check this before designing lesson 9.
- `vally lint` reports a misspelt key (`eval-load-error`, with the allowed names) and a missing file (`environment-file-not-found`).

From authoring lessons 5 to 8 (2026-11-10):
- Diff graders see the whole patch, context lines included. A pattern for added lines needs `(?m)^\+`. Without `(?m)`, `^` matches only the start of the patch, so `diff-not-contains` with `^\+…` can never fail. The author made this mistake for real; lesson 8 teaches it.
- A run saves each trial's diff (in `<run>/diffs/`, referenced by `trajectory.diffPath`) only when its eval file has a diff grader. Runs without one cannot be re-graded with diff graders ("No workspace diff is available").
- Re-grade a whole saved run from inside its folder: `vally grade -e ../../../evals/changelog.eval.yaml --run-dir . < results.jsonl`. Output blocks name the stimulus, not the model.
- **In a re-grade, script graders fail on every trial** (the workspace is gone) and are reported as ordinary failures. `run-command` says `Expected exit code 0, got 1`; `program` with a script that crashes says `Grader exited with exit code 1`; our `check-entry.mjs` checks for the file and says `no CHANGELOG.md to check`. Only diff graders are trustworthy there.
- `run-command` evidence on failure is only "Expected exit code 0, got 1". The script's own stderr message is not recorded.
- A `program` grader must print Vally's full result object; `{passed, evidence}` alone is rejected with "Grader output did not match schema". The docs example uses `name`, `kind`, `passed`, `score`, `evidence`.
- `--workspace <dir>` keeps workspaces at `<dir>/main/<stimulus>/`. A kept workspace for the one-request eval held `CHANGELOG.md` and `changelog-entry/SKILL.md` only.
- `vally lint` rejects a grading file staged from inside a skill folder: `grading-file-src-agent-visible`.
- A saved trial's `workspace.patch` works as a `golden_patch` unchanged.
- Oracle wording: with golden, "PASSED"; without, "failed as expected", "N/A — pass allowed on the empty baseline" for absence graders, and "passed without the golden solution (trivially passing)" with "baseline PROBLEM" and exit 1 for a useless grader. A stimulus with no golden patch is skipped, or refused if named with `--stimulus`. Vally calls the untouched state the "baseline", so the plan now introduces that word in lesson 7.

From the earlier real runs (2026-11-09), still true:
- Model names vary by account. An unavailable name is an `ERROR` that lists the account's models, exits 1 and spends no agent run.
- Default five workers dropped 3 of 10 sessions; two workers ran all 10.
- A plain `vally eval` worked with an existing Copilot CLI sign-in and no token variable. With `EVALUATE_USE_HOST_COPILOT_HOME=1` a run aborted after loading the user's own hooks and MCP servers; cause not isolated.
- The Copilot runtime comes with the CLI.
- `agent_environment.skills` copies the whole skill folder into the workspace, including any `evals/` inside it.
- `vally lint` rejects a `grading_environment` source the agent can see (`grading-file-src-agent-visible`).
- `golden_patch.path` rejects `..`, so the patch sits beside or below the eval file.
- Lint one eval file with `vally lint -e <file>`.
- Grader names must be unique within an eval file.
- `vally grade -e <file>` uses that file's graders and rubric, matched by stimulus name. `vally grade --output jsonl` records have no `.type` or `.stimulus`; the name is `.gradeResult.stimulusName` and grader results are in `.gradeResult.details[]`.
- `vally oracle` can pass a grader in both directions and the grader can still fail a good real answer.
- Report columns for repeated trials read Pass Rate, pass@k and pass^k.
- Suite selection, `--require-pass` (exit 1 on a failing verdict) and `--junit` work as documented.
- `paths.results` in `.vally.yaml` is never read; output goes to `--output-dir` or `./vally-results`.
