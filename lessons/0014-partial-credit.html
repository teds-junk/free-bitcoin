This lesson gives the judge a scale, and shows the one way partial credit goes wrong: an average that lets a failure pass.

When a score beats a yes or no

Lesson 12 asked for yes or no, because a yes-or-no criterion has to be clear and a 3 against a 4 rarely is. That advice still holds for the question "did it pass?". A scale is worth adding when the work really can be partly right, and you want to know how far off a failure is: nearly there, or nowhere near. Wording is like that. An entry can be mostly for users with one word of implementation in it.

Other checks are not like that. An entry either cites pull request 66 or it does not; a security fix is either under Security or it is not. There is no "nearly" for these, and a skill that gets one of them wrong has failed, however good the rest is. Vally's own guidance draws the same line: "Thresholds are for genuinely graded work — judged quality, partial credit — not for pass/fail assertions like file-exists." Keep checks that must all hold out of any score that is averaged.

The sources this course leans on do not fully agree here. Husain and Shankar argue for yes-or-no judges throughout; Anthropic's guide to agent evals treats partial success as a range worth recording. They agree on the part that matters for this lesson: whatever the scale, you still decide pass or fail with a clear line, and you check that line against your own labels.

Sources: Vally docs, Scoring, for the quotation; Hamel Husain, Using LLM-as-a-Judge; Anthropic, Demystifying evals for AI agents (2026-01-09).

How Vally turns grader results into a verdict

Every grader gives a score between 0 and 1 as well as a pass or fail. A pass-or-fail grader, such as diff-contains, scores 1 when it passes and 0 when it fails. For each trial, Vally combines its graders' scores into one score. What decides the trial's verdict depends on one optional part of the eval file.

The scoring block

An optional top-level scoring: section of an eval file. It applies to every stimulus in the file. It can hold weights, how much each grader type counts towards the trial's score, and a threshold, the score from 0 to 1 that a trial must reach to pass.

With no scoring block, which is what every eval file in this course has had, every grader must pass. Vally still works out a score, the plain average of the graders' scores, and prints it, but the score does not decide anything. vally lint says so in its warning on evals/wording.eval.yaml:

⚠ warning [scoring-defaults-applied] Multiple graders
  with no scoring config
  Using defaults: equal weights, no threshold — the
  verdict is binary, so any single failing grader fails
  the stimulus.

That is the one warning you have seen from vally lint since lesson 5.

With weights and a threshold, the trial passes when its weighted score reaches the threshold, whatever any single grader said. The block sits at the end of the file, at the same level as stimuli:

evals/wording-scaled.eval.yaml (the end, with a scoring block)
73 lines hidden: the whole eval file, three stimuli
scoring:
  weights:1
    prompt: 0.5
    diff-contains: 0.5
  threshold: 0.62
  1. Weights are keyed by grader type, not by grader name. Graders of the same type in one stimulus are averaged first, then the type's weight applies. Here the judge and the pull request check count equally. Vally's lint expects the weights to add up to 1.
  2. The trial passes when 0.5 × the judge's score + 0.5 × the check's score is 0.6 or more. Sixty percent sounds like a fair bar. This lesson uses it to show what goes wrong, not as advice.

Two rules follow from the arithmetic, and both can hide a failure.

  • A strong score on one grader can carry a failure on another. A trial whose judge scored 0.25 (the next section shows how a judge can score between 0 and 1) and whose pull request check passed has a weighted score of 0.625, which reaches 0.6, and passes. The judge's failure is still printed with a cross; it just no longer decides the verdict.
  • A grader type left out of weights stops counting. Its weight is taken as 0. Weights of diff-contains: 1 alone would make the judge a passenger: it would still be called, still cost a judge call, and its verdict would change nothing. The docs put it plainly: "Omitting a type silences it, so list every type you care about."

A threshold with no weights uses the plain average of every grader.

A stimulus has a judge that fails (score 0) and two diff graders that pass. The file's scoring block has no weights and a threshold of 0.6. What is the verdict?
Right. With a threshold and no weights, all three graders count equally: (0 + 1 + 1) ÷ 3 is 0.67, which reaches 0.6. The judge's failure is outvoted.
It passes. With a threshold set, a single failing grader no longer fails the trial. With no weights the three scores are averaged: (0 + 1 + 1) ÷ 3 is 0.67, which reaches 0.6. The judge is not ignored; it is outvoted.
Sources: Vally docs, Scoring; the rules for a missing type and for a threshold with no weights were checked in Vally 0.21.0's scoring code, and the lint warning is from our run on 2026-11-10.

A judge on a scale

The prompt grader's scoring setting, which you set to binary in lesson 12, has two other values: scale_1_5, which is what a judge uses if you leave scoring out, and scale_1_10. This lesson uses scale_1_5. Do not confuse it with the scoring block above: this one is inside the judge's config and changes only how the judge answers.

With scoring: scale_1_5, the judge gives each rubric criterion a whole number from 1 to 5. Vally rescales it to the range 0 to 1, so that it can be combined with other graders' scores: 1 becomes 0, 5 becomes 1, and each step is a quarter. The judge passes when its rescaled score reaches its own threshold. Leave the threshold out and it is 0.5, which means a 3 passes.

So there are two thresholds, with two jobs. The judge's own threshold decides the judge's tick or cross. The scoring block's threshold decides the trial. With no scoring block, the judge's tick or cross is what counts, because every grader must pass. With a scoring block, only the judge's score counts, and its own threshold changes nothing about the verdict.

One thing to know before you read the output. vally grade prints a reason and a tick or cross for the judge, and a Score line for the trial, but not the judge's own number. In our trials every pull request check passed and scored 1, so the Score is the average of 1 and the judge's score, and you can read the judge's answer straight off it:

Score line100%87.5%75%62.5%50%
Judge's answer54321

If a trial's pull request check fails, its Score is half the judge's rescaled score, and the table does not apply.

Sources: Vally docs, Grader: prompt, for the scales, the rescaling and the default threshold. That the judge's own number is not printed is from our run on 2026-11-10 with Vally 0.21.0.

What the scores showed

The scale did separate "nearly" from "far off". The four entries from haiku that said how the change was coded, "LRU caching", "LRU cache for tag index", "streaming JSON parser" and "streaming parser in importer.js", all got 2. The two terra entries that lead with what users notice and end "by caching the tag index" got a 4 and a 3. That is the entry we hesitated over in lesson 12, and the judge hesitated too. If we were choosing what to fix in the skill, the 2s say where to start.

It also changed a verdict, and not for the better. With the judge's threshold of 0.75, terra's "on large folders" cache entry passed, where we and the yes-or-no judge had failed it: TNR fell from 6 of 6 to 5 of 6. The default threshold of 0.5 would let every 3 through as well, and its twin got a 3. A threshold is a decision about where "good enough" starts, and the only way to know whether it sits where you would put it is the same check as in lesson 13: compare its verdicts with your labels.

Two more things showed up when we judged the same twelve entries again. Across our three runs, each grading the trials twice, terra's two cache entries got a 4 eight times and a 3 four times. Each 4 is a pass and each 3 a fail, so the verdict on the same entry flipped from one grading to the next. Scores near the threshold are where a judge's run-to-run variation turns into a different verdict. The haiku entries that said how the change was coded got a 2 in every grading. And the scale invited the judge to mark things the rubric did not ask about: date entries got a 4, not a 5, for being "a little generic", "slightly generic" or "slightly terse", or for lacking "a concrete example date". A one-criterion rubric keeps a yes-or-no judge on its question more easily than it keeps a 1-to-5 judge there.

The judge failed each of them, in plain words, and each passed as a trial, because the pull request check scored a full 1 and the average carried it. With half the weight on a check that nearly always passes, a threshold of 0.6 asks the judge only to avoid a 1. Every one of the twelve trials passed, so nothing in the run's summary would tell you the wording rule was broken four times; you would have to read the cross inside each block. That is how a failure hides in an average, and why Vally's advice is to keep thresholds for judged quality and leave pass-or-fail checks out of weighting. For the rest of this course the yes-or-no judge decides the verdict, and the 1-to-5 judge is a tool to reach for when you want to know how far off a failure is.

Exercises

  1. From memory, say what decides a trial's verdict with no scoring block, and with weights and a threshold.
    Show model answer

    With no scoring block, every grader must pass; the printed score decides nothing. With weights and a threshold, each grader type's average score is multiplied by its weight, and the trial passes when the weighted score reaches the threshold, even if some grader failed.

  2. Suppose the scoring block in step 6 had said weights: with only diff-contains: 1, and threshold: 0.75. Using our scores, how many of the twelve trials would pass, and how many judge calls would the re-grade cost?
    Show model answer

    All twelve would pass, because every entry cites its pull request and the judge's type is left out of the weights, so it counts for nothing. The re-grade would still cost twelve judge calls: the judge runs and prints its crosses, and they change no verdict. We worked this out from Vally's rule rather than running it.

  3. A teammate weights a judge at 0.8 and a "cites the pull request" check at 0.2, with a threshold of 0.8, so that the judge dominates. A trial gets a 5 from the judge and has no pull request number. Does it pass, and what would you change?
    Show model answer

    It passes: 0.8 × 1 + 0.2 × 0 is exactly 0.8. A missing number is a failure, not a lower grade. Keep the judge's scale if you want it, but take the check out of the averaging: leave the file with no scoring block, so that the check and the judge's threshold must both hold.
