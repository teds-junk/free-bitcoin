So far: You have five stimuli with graders, two of them graded by a script the agent cannot see, and those graders now decide whether your skill is improving.

This lesson answers: How do I know a grader passes correct work and fails missing work?

Every decision you make about the skill from here on rests on the graders. If one of them is wrong, you will "fix" things that were fine or, worse, believe a failure is gone when the grader simply cannot see it. A grader is a small program, and programs have bugs. So before trusting one, test it. The pleasant surprise of this lesson is that testing a grader needs no agent at all, costs nothing, and takes seconds.

Two ways a grader can be wrong

A grader gives one of two answers, so it can be wrong in two ways.

  • It fails correct work. The agent did the right thing and the grader objects anyway, perhaps because it insists on one exact wording. You then chase a problem that is not there.
  • It passes work that was not done. The grader is so loose, or so broken, that it is satisfied by anything, including nothing. You then stop looking at a problem that is still there.

To test for each, you need the matching example. For the first, a result you know is correct: if the grader fails it, the grader is wrong. For the second, a result you know is empty, the starting files with nothing done: if the grader passes that, it is not checking the work.

You have used a rough form of the second test already. In lesson 5 you ran new graders against the skill before editing it and watched each one fail. This lesson makes both tests exact, and repeatable.

A golden patch

Golden patch

A patch you keep, which records exactly the changes a correct answer would make to the starting files. "Golden" is the usual word for a reference answer that is known to be good.

You have been reading patches since lesson 1, and you already own several correct ones: every trial whose workspace.patch you read and judged right. A golden patch is one of those, copied to a place where you keep it. This is ours for the typo-fix stimulus. It is the patch from a trial in lesson 6, unchanged.

What vally oracle does

vally oracle runs your graders against a known answer, with no agent involved. In testing, an oracle is a source of answers known to be right. The command takes -e and the eval file, as vally eval does, and works in one of two ways.

Plain vally oracle does the left column. It builds the workspace exactly as for a real trial, applies the golden patch where an agent would have worked, and runs the graders. Applying a patch means making the changes it records: its + lines are added to the file. A grader that fails here is failing a correct answer.

Adding --no-golden-input does the right column: the same workspace with nothing applied. Vally's name for this untouched state is the baseline.

Baseline

What you compare a result against. For the oracle, the baseline is the workspace with nothing done to it.

On the baseline, a grader ought to fail, and the oracle reports that as good news: failed as expected. There are two other things it can say.

The oracle saysMeaning
failed as expectedThe grader failed the untouched workspace. It depends on the work being done. Good.
N/AThe grader checks that something is absent, such as diff-not-contains or diff-empty. An untouched workspace passes it honestly, so this test cannot tell you anything about it.
trivially passingThe grader passed the untouched workspace and is not an absence check. It does not depend on the work at all. The oracle prints baseline PROBLEM and exits with an error.

Two more options are used in the checkpoint. --stimulus and a name limits the oracle to one stimulus. --verbose prints each grader's evidence. Without --stimulus, the oracle covers every stimulus that has a golden patch.

You run vally oracle --no-golden-input. A diff-not-contains grader passes on the untouched workspace. What does the oracle do?
Right. A grader that checks for absence is bound to pass when nothing was done, so the oracle marks it N/A. It has not been tested.
It marks it not applicable and exits with zero. A grader that checks something is absent will always pass an untouched workspace, so the oracle cannot test it this way and says N/A.
Sources: Vally docs, CLI: oracle; the wording of each report is from our runs on 2026-11-10 with Vally 0.21.0.

Prove your graders

You will keep one correct trial as a golden patch, run the oracle both ways on that stimulus, watch it catch a deliberately useless grader, and then do the same for the other stimuli. No step starts an agent.

What the oracle did not test

Look at our table and ask which graders have now been tested in both directions. Four have: they pass a correct answer and fail an empty one. Two have not. no-made-up-number and adds-nothing are both checks that something is absent, and "N/A" is the oracle saying honestly that an untouched file cannot test them. Nothing so far has shown that no-made-up-number would object to a made-up number.

There is a second limit. The oracle tested each grader against one correct answer, the one you chose. A different correct answer, worded another way, has not been tried.

CLI: oracle, Vally docs

Read the section on the baseline. It lists every kind of grader the oracle treats as N/A, which tells you in advance which of your graders it cannot vouch for.
