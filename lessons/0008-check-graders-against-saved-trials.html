Saved trials are tests for graders

Every trial you have read is an example with a known answer. You know which ones are right and which are wrong, and why. That makes them the best material you have for testing graders, in two ways the oracle cannot manage.

A trial you know is bad tests a grader that checks for absence. If no-made-up-number does not fail a trial where the model wrote (#42), the grader is broken, whatever the oracle said. The rule is simple: every "must not" grader should have at least one saved trial that it fails.

A trial you know is good, in different words, tests whether a grader is too strict. The oracle tried one correct answer per stimulus. Your saved runs hold several, each worded a little differently. A grader that fails one of them is objecting to wording, not to a fault.

When a grader and your own reading disagree, do not assume either is right. Open the evidence and the patch, and decide. You have already seen it go both ways. In lesson 5's first run, before the skill had any rule for a missing number, one trial asked for the number instead of making one up. That was a defensible answer, and the grader adds-an-entry failed it. In lesson 6 a script failed trials that looked fine at a glance, and the patches showed the script was right; in the same lesson it passed a trial that was wrong.

Re-grading a saved run

vally grade runs graders over trials that are already saved. No agent starts, so it costs nothing. It needs three things:

  • -e and the eval file. The graders used are the ones in the file as it is now, matched to each saved trial by stimulus name. Change a grader, and the next re-grade uses the changed one.
  • The saved trials, fed in from the run's results.jsonl. The < sign before a file name gives that file to the command as its input.
  • --run-dir and the run's folder. Each trial's folder has a workspace.patch for you to read. When the eval file has a diff grader, meaning any of the three graders from lesson 5 that read the patch, the run also keeps a copy of every trial's diff in a folder named diffs. A re-grade reads those copies, and --run-dir tells it which run folder to look in.

It prints one block per saved trial: the stimulus name, a tick or a cross, and each failing grader with its evidence. The blocks do not name the model.

There are two limits, and both matter.

What a re-grade can and cannot judge

A run keeps the copies in diffs only if its eval file had a diff grader at the time. Your runs from lesson 5 onward did. The runs from lessons 3 and 4 did not: their trial folders still have a workspace.patch for you to read, but there is nothing for a diff grader to re-grade.

A script grader needs the workspace, and the workspace is gone. In a re-grade, a script grader fails on every trial, including trials that really passed, and our script says why: no CHANGELOG.md to check. Ignore script graders in a re-grade. Test those with the oracle.

The checkpoint uses a real mistake to show what a re-grade can catch.

When we first wrote no-made-up-number, the pattern was this:

pattern: '^\+.*\(#\d+\)'

It is the pattern from lesson 5 without the (?m) at the front, and it reads correctly: a line starting with a plus sign that contains a number in brackets. It is wrong. Without (?m), the ^ means the very start of the whole patch, and a patch never starts with a plus sign. So the pattern can never be found, and a grader that passes when a pattern is not found will pass everything.

Right. A script grader reads files in the workspace, and saved runs keep the diff, not the workspace. The failure says nothing about the trials.

Catch a grader that cannot fail

You will re-grade your "before" run from lesson 5, put the flawed pattern in, see the oracle accept it, see the saved trials expose it, and put the right one back.

The oracle says yes; the saved trials say no

  1. Goal: find the run where you know failures happened. Open a terminal in practice. 
    ls results/lesson-5-before

    You should see: one folder named with a time. Use its name in the next step.

  2. Goal: move into that run's folder, so the paths stay short. 
    cd results/lesson-5-before/2026-11-10T14-55-35-995Z
  3. Goal: re-grade the saved trials with your graders as they are. This starts no agent. 
    vally grade -e ../../../evals/changelog.eval.yaml \
  --run-dir . < results.jsonl
    ━━━ typo-fix ━━━
❌ typo-fix (1/2 graders passed, 1 failed)

    You should see: eighteen blocks, one per saved trial. Find the six for typo-fix. In our run three passed and three failed, matching the count from lesson 5. Two of the failing ones name no-made-up-number. The third names adds-an-entry: in that trial the model asked for the number and wrote nothing. The dot after --run-dir means "this folder".

  4. Goal: put in the pattern that looks right and is not. This edits one file. In your text editor, open evals/changelog.eval.yaml from practice. In the no-made-up-number grader, delete the four characters (?m) from the start of the pattern, so that it reads as the flawed one shown earlier. Your terminal stays where it is.
  5. Goal: ask the oracle about the changed grader. Go back to practice first. 
    cd ../../..
    vally oracle -e evals/changelog.eval.yaml \
  --stimulus typo-fix --verbose
    vally oracle -e evals/changelog.eval.yaml \
  --stimulus typo-fix --no-golden-input --verbose

    You should see: PASSED from the first, and from the second N/A for no-made-up-number and a last line beginning baseline OK. The oracle has no complaint.

  6. Goal: ask the saved trials about the changed grader. 
    cd results/lesson-5-before/2026-11-10T14-55-35-995Z
    vally grade -e ../../../evals/changelog.eval.yaml \
  --run-dir . < results.jsonl
    ━━━ typo-fix ━━━
✅ typo-fix (2/2 graders passed)

    You should see: no typo-fix block that names no-made-up-number, including the trials where you know a number was made up. In ours, five of the six passed; the sixth still failed adds-an-entry, the trial that wrote nothing. The grader cannot fail.

  7. Goal: put the correct pattern back and confirm it. This edits one file. Restore (?m) at the start of the pattern. You are still in the run folder, so run the vally grade command from step 6 again, without its cd line.

    You should see: the same count as in step 3. Then return to practice with cd ../../...

A habit for every grader

Four characters were the difference between a grader that works and one that approves everything, and the oracle could not tell them apart. This was a real mistake, made and caught while writing this course, and it was caught the way you just caught it: by running the grader on a trial known to be bad.

The same re-grade settled your other absence grader without any extra work. Look at the refactor blocks from step 3: adds-nothing failed all six, on trials where both models recorded the refactor. Both "must not" graders now have saved trials that they fail.

Make this a habit whenever you write or change a grader. Run the oracle, which is free. Then re-grade a saved run where the failure is known to occur, which is also free. Only then spend agent runs.
